## 保留哪些版本

按实际支持需要判断，不按“大版本全部保留、小版本全部丢弃”决定。
仍有用户或报告、明确代码分支、升级恢复需求时，保留必要兼容差异。
其他范围没有验证就说明未验证，不从本机外推。

同一事实优先在原条目分列机型或 ROM 差异；新版本替代唯一开发目标时直接更新正文。
只有差异已形成独立实现或大量独立资料时才拆专题页。
退出支持后的资料，只保留有排障或决策价值的部分，其余删除。

## 系统升级或换机的最小流程

1. 读取机型、ROM 指纹与身份，更新本页的开发基线。
2. 按当前任务检查相关服务、可读节点、配置格式以及必要的控制和恢复；
   App 功能通过实际执行器验证。全量功能复测由变更风险决定。
3. 更新受影响的事实、命令和兼容分支，清理旧说明与完成的任务。

温控可以现场读文件；其他功能使用能力探测和可用读回。
换基线不要求复制一套文档或保留每次瞬时状态；日期用于标明测试条件，不代替兼容判断。
