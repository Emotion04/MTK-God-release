# 温控档位说明

本文是随应用提供的参考说明，仅适用于 vivo V2430A、Android 16、ROM `PD2430D_A_16.1.12.0.W10`。换机型或 ROM 后，文件和档位含义可能变化。

应用能读取并解析设备配置时，界面生成的实时档位摘要优先于本文。本文只在实时解析不可用时作为参考；不能据此判断其他版本的当前状态。

## 当前设备已核实的内容

- 2026-09-26，设备 `/vendor/etc/thermal/` 中有 13 个可选索引：`00`、`01`、`02`、`03`、`05`、`07`、`08`、`09`、`10`、`11`、`12`、`13`、`18`。应用会从设备目录动态发现索引，未列出的编号不代表设备上存在对应配置。
- 干净重启后、没有本项目遗留请求时，系统默认读取主配置 `thermal.conf`，不等同于手动索引 `01`、`08` 或 `09`。皮温 41.6 °C 时，`policy7` 的 `scaling_max_freq` 实测为 2100000 kHz。
- 手动选择索引 `01` 的对照中，该配置没有 CPU 频率表；在本机测试条件下，`policy7` 上限曾从主配置约束下的 2100000 kHz 变为 3400000 kHz。此结果只适用于上述设备和 ROM，不表示其他档位有相同效果。
- 2026-09-26 在线快照读到静态阈值 `39/41/44/47/60/80 °C`，`IsStatusOverride=false`。阈值与主配置相符；皮温是瞬时值，不在本文保留；这次在线快照没有重启设备，不能替代干净启动对照。

## 如何判断档位和当前状态

应用显示的编号对应设备上实际存在的 `thermal_policy_NN.conf` 文件。读取配置生成的 CPU、GPU、温度和充电摘要描述的是文件内容，不自动证明该策略此刻正在生效。

“当前皮温阈值”来自 Android thermal service。它可以帮助比较当前运行状态与已读配置，但不是档位编号；多个策略可能有相同阈值。单看阈值不能确认是哪一个应用或场景触发了策略。

固件配置中的应用包名和 powerhint 只证明存在静态选路规则。实际触发条件仍需在对应场景下观察，不能把配置表直接当作已复现的运行行为。

项目内的来源、文件哈希和完整配置索引见 `docs/thermal/configs/README.md`；当前结论与适用范围见 `docs/thermal/facts.md`。历史实验见 `docs/experiments/EXP-20260926-01-clean-boot-thermal-policy.md`。
